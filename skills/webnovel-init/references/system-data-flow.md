# Init data flow

The author conversation collects and confirms choices. The Skill serializes only confirmed structured data to `<WEBNOVEL_HOME>/tmp/init/`. The runtime validates the request and renders a zero-write preview. A preview token binds request content, destination observations, Git mode, blockers, and the exact write plan; it is not user consent.

The preview also returns a finite `Apply` / `Revise` / `Cancel` choice and an exact `WEBNOVEL_INIT_APPLY_CHOICE/v1` assistant marker bound to the project root, token, Git mode, and write list. Apply requires both the fresh token and a separate `webnovel-init-apply-authorization/v1` artifact. That artifact points to the host-owned Codex sessions root and current parent rollout. The runtime requires its parent thread to equal the canonical nonzero UUID inherited from host-owned `CODEX_THREAD_ID`, verifies the parent model/effort, reads the first user answer after the unique marker, requires `Apply`, and matches the SHA-256 of rollout bytes through that answer. Missing, malformed, mismatched, stale, duplicated, caller-asserted, free-form, `Revise`, or `Cancel` authorization fails closed.

Apply is missing-only. It creates `.webnovel/state.json`, `.webnovel/idea_bank.json`, core `设定集` files, `大纲/总纲.md`, `.story-system/MASTER_SETTING.json`, and anti-pattern contracts. Existing authored Markdown that remains valid UTF-8, nonempty, structurally complete, and consistent with canonical identity is preserved byte-for-byte, including later prose edits; other missing files are still filled. Empty, corrupt, structurally incomplete, or contradictory controlled Markdown blocks preview. Existing controlled JSON must parse and match the confirmed book identity and constraints or the workflow stops.

The Story System is canonical for runtime constraints; `.webnovel` is a compatible state/read-model area. Neither is edited directly by the Skill. Reference analysis is provisional until runtime evidence, quality, transformation, and user-adoption gates all pass. Reference adoption has its own exact `WEBNOVEL_INIT_REFERENCE_CHOICE/v1` marker and `Adopt` / `Discard` / `Cancel` choice. Its deterministic confirmation object scopes the choice but does not prove consent; the runtime requires a real `Adopt` answer in the trusted parent rollout, binds the prefix through that answer, and requires both parent evidence and child-parent identity to match the same host-injected current task UUID.

`CODEX_THREAD_ID` must be inherited unchanged; Init commands must never assign or override it. This is host-bound live evidence observed in Codex Desktop, not cryptographic protection from a local process that can alter its environment. If the variable is absent, malformed, or mismatched, Apply and reference adoption remain pending with zero target writes.

Git mode defaults to `off`. When explicitly selected, Git commands use `git -C <resolved-novel-root>` and an allowlist. Parent repositories, `git add .`, and implicit commits are forbidden. `initial-commit` disables hooks only for its exact commit subprocess so a global `core.hooksPath` cannot execute untrusted hooks.
